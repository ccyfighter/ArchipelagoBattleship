Android 14+ 原生策略战棋（Kotlin + Jetpack Compose Material 3 + Coroutines/StateFlow +
kotlinx.serialization）。单机 AI 对战 / 双机面对面局域网联机。

> 舰种数值直接从舰船目录生成，不再手写两遍。战斗页合并重复战报入口、折叠图例、收紧状态区，
> 首页与大厅同步压缩，正文只留操作与状态。

## 五、玩法与交互流

### 房间状态机
- `ROOM_LOBBY`：文字聊天 + 快捷战术表情；房主可切 10×10 快棋 / 12×12 标准（默认） / 14×14 大战场，
  12×12 与 14×14 显示【随机群岛】勾选框（默认勾选有山，取消 = 纯海），改动实时同步客机；
  双方各自选船布阵 → 准备 → 房主点「开始战斗」。
- `IN_BATTLE`：聊天输入框与发送**立即禁用/隐藏**；棋盘 + 战况播报 + 180s 倒计时。
- `POST_BATTLE_LOBBY`：任一方全灭弹结算（双方存活/击沉明细、回合数、MVP）；
  点「返回房间」→ **不断开连接、不退出房间**，回到大厅，聊天重新解锁，
  房主可重调地图 / 山地，双方可换船重开下一局。

### 舰队（严格 5+4+3+2+1，共 15 格）
| 格数 | 可选舰种 |
| --- | --- |
| 5 | 航空母舰 / 战列舰 |
| 4 | 航空巡洋舰 / 火力巡洋舰 |
| 3 | 潜艇 / 防空巡洋舰 / **雷达哨舰**（v9 新增） |
| 2 | 驱逐舰 / 反潜舰 |
| 1 | 高速炮艇（必选） |

全部技能（侦察机 CD3/全局5次、绝境副炮、航母本体点防空、主炮齐射 CD3、
鱼雷机空袭（起点 + 3 步 / 单点爆炸）CD3/全局2次、高能燃烧弹全局2发+AA瘫痪、潜航鱼雷+潜望镜一击必沉+强制上浮、
区域防空网、**监视雷达**、紧急规避机动全局1次、深水炸弹炮、**主动水听声呐 13 格 + 地形阻挡**、灵活规避、
呼叫陆航空袭延时1回合且无视一切AA）都在 `domain/engine/GameEngine.kt` 中实现，
编成界面会展示当前选中舰种的完整数值说明。
侦察机 / 水听声呐 / 监视雷达 / 主炮齐射 / 鱼雷机空袭自第 2 回合起可用，燃烧弹第 3 回合起，陆航空袭第 4 回合起。
侦察机扫描成功后，敌方棋盘会把扫过的十字 5 格标成「侦察区」放大镜（只显示扫描区，不显示舰船坐标）。

### v9：情报层与传感器（详见文末「九、v9」）
- **击落判定只看部署点**：侦察机 / 鱼雷机 / 轰炸机的「扫描范围 / 航线」都不参与 AA 判定；
  航母本体 5 格、防空巡洋舰每格外扩 1 圈（共 15 格）才是防空区。
- **侦察机可看到水下潜望镜**：水下潜艇的中心第 2 格进入十字 5 格即计数，与上浮与否无关。
- **水听声呐**：只探测潜艇；范围 3×3 + 四边中间外突 1 格 = 13 格；山地阻挡声波（山后不计）。
- **监视雷达（雷达哨舰，3 格）**：以本舰船体为源点向八方向发射射线，遇山即止；
  10×10 / 12×12 射程 2 格、14×14 射程 3 格；只返回「水面舰艇 + 已上浮潜艇」的条数，
  敌舰任一格进圈即计入，不报坐标 / 舰种；无需选点。
- **拦截 / 免疫 / 阻挡不再封锁坐标**：这些记录只画紫色盾标记，不写 `attackedPoints`，
  同一格后续仍可由其他舰船开火。四种情报覆盖层也全部是纯显示层。

### 回合流
回合初自动结算延时空袭 / 刷新 CD / 解除 AA 瘫痪 / 更新潜艇上浮（含【上浮暴露复核】）→
阶段一（可选 1 次战术行动，或显式点「进入阶段二」）→
阶段二（攻击名额 = min(存活舰船数, `Rules.BASE_ATTACKS_PER_TURN`，默认 3)，每舰 1 次，随时可结束回合）
→ 180s 超时按剩余未行动舰船数自动随机常规炮击并结束回合。
所有操作都是「选船 → 选目标（可反复改） → 点确认」，不自动切船、不自动释放技能、不自动跳阶段；
本回合内可「撤销 / 重做」，换手自动清空撤销栈。
除十字 5 格范围伤害外，单点攻击禁止选已攻击过的格子（候选格高亮 + 引擎二次校验）。
棋盘采用「底色 + 形状 + 颜色」三重编码：高对比内缩描边框+角点=可攻击、灰斜纹=已打过、
琥珀放大镜=侦察机、蓝色同心波纹=水听、青色虚线框=监视雷达、橙红斜叉=陆航空袭预告、
蓝空心圆环=未命中、红圆白叉=命中、深红整船残骸框=击沉、
紫菱形盾=拦截/免疫/阻挡、橙色呼吸双框=最近一击；棋盘下方有 12 项矢量图例，
顶部另有最近 3 条战果彩色横幅。v10 起默认开「情报视图」隐藏全部可打击标记、
并压掉交错格明暗 / 手绘细网格 / 声呐同心圆，点任意格子弹出该格战况检查卡；
完整战报在整屏面板里查看，不再需要一边滚页面一边滚小列表。
四种情报覆盖层只画在「扫描者看到的敌方海域」，对方自己的棋盘会做脱敏，看不到你在看哪里。

### 【潜望镜一击必沉】（潜艇专属）
水下潜艇的中心第 2 格是唯一暴露点。任何能命中该格的攻击（常规炮击 / 舰载机炸弹 /
深水炸弹 / 鱼雷 / 无视 AA 的饱和空袭）一旦命中，直接判整艇沉没；战报按统一格式只播报坐标与结果（击沉才公开舰种）；
沉船守卫随即禁止它再开火或释放技能，不会再出现「带伤发射鱼雷、等上浮才沉」。
只有落在首尾两格的 MISS 才走下面的【上浮暴露复核】。

### 【上浮暴露复核】（潜艇专属，解决"打过的格子锁死"）
水下潜艇首尾两格被常规炮击时按规则反馈「未命中（水花）」，同时坐标会进入去重集合。
若潜艇此后强制上浮，这些格子本应可被击中，却因去重无法再打。处理方式是：
**上浮那一刻自动把此前「因潜望镜隐蔽而报 MISS 的单点炮击」复核为命中**，
直接对潜艇造成 1 格伤害、棋盘上对应 ○ 自动变 X、战况只播报「该坐标的既有攻击复核为命中」，
命中按原攻击者归因（MVP 统计不漏）。玩家不额外获得攻击机会，坐标依旧保持去重，
也不会因为"哪些格子被解锁"而泄露潜艇位置。
只匹配落在潜艇首尾格、且当时「没找到船」的单点 MISS；空海水花、十字范围伤害、
「该舰格已损毁」、侦察 / 深弹 / AA 拦截等记录一律不参与，其他舰船打击逻辑零改动。
复核后记录由 MISS 改为 HIT，因此后续再次上浮不会重复结算。

### 鱼雷机空袭（航空巡洋舰）
阶段二技能，第 2 回合起 / CD3 / 全局 2 次：先点投雷起点，再点与其同行或同列的一格指定航向
（第二点仅定方向，不要求该格未被攻击过）。鱼雷从起点沿航向向前推进 3 格（航线共 4 格，
例如 M14 向西可打到 J14），**只在一处爆炸、只结算一次伤害**：
① 碰到第一艘未沉敌舰 → 该格爆炸；② 前方是山地 → 在撞山前一格爆炸（起点即山地则空袭无效）；
③ 都没遇到 → 在射程尽头一格爆炸。伤害判定与潜航鱼雷完全相同（同为 `AttackKind.TORPEDO`，
可命中水下潜艇、不受炮艇「灵活规避」影响）；沿途不写 ShotRecord、不画轨迹，
棋盘只在爆炸点留下一个命中 / 未命中标记，中间格以后仍可用火炮正常打击。
**AA 圈外视距打击**：防空判定只检查「投雷起点」这一个部署点 —— 起点在敌方航母 /
防空巡洋舰防空圈外，飞机即可投雷，即使爆炸点落在防空舰身上也照常结算；
只有起点落进防空圈才被击落、整次空袭失效。爆炸点属于范围伤害，不写入坐标去重。

### 沉没舰船
已沉没舰船在所有行动入口（开火 / 技能 / AI / 超时托管）统一被拦截，且会给操作者一条
仅自己可见的 `【已沉没】… 无法再开火或释放技能` 提示；界面同步移除其选船与技能按钮。敌方棋盘上仍会保留
已沉舰的矢量图标（这是"战果展示"，不是该舰仍可行动）。

### 地形
12×12 / 14×14 且勾选山地时生成 3~8 座随机群岛（单岛 1~6 格，形状随机，可贴边角，
岛间留 1 格，总面积 ≤ 20%，双方使用同一份地形因此无需对称）；
山地不可部署 / 不可攻击 / 阻挡鱼雷；紧贴 1 圈为近岸浅滩，
3~5 格大舰与潜艇禁入，1~2 格小舰（含炮艇）可入。

### 联机
- 房主：`ServerSocket` 监听随机端口 + `NsdManager` 广播 `_archipelago._tcp`，
  大厅直接展示含 `IP:Port + 房间密钥` 的二维码。
- 客机：扫码（CameraX + 纯 ZXing）/ 搜索附近房间 / 手动输入 `IP:端口:密钥`，
  三路都走同一条 Socket 长连接。
- 权威状态在房主，客机只发 `GameAction`、收脱敏 `GameView`（敌方未沉舰船不下发），
  避免隐藏信息泄露与状态不同步。
- 权限：`NEARBY_WIFI_DEVICES`（`neverForLocation`）、`ACCESS_NETWORK_STATE`、
  `ACCESS_WIFI_STATE`、`INTERNET`、`CAMERA`，运行时动态申请。

## 六、如实说明的工程取舍

1. **房主是权威端**：客机的布阵会发给房主（面对面娱乐对局，不涉及公网与隐私数据）。
   换来的是零状态不同步、聊天/倒计时/结算全部由一处裁决。
2. **回合编号**：`round` 为「双方各行动一次」的配对回合；A 先手、B 后手，
   B 结束后 `round+1`。「第 2/3/4 回合起可用」以此为基准，双方公平。
3. **AI**：单机 AI 使用 Hunt & Target 决定攻击坐标，攻击方式以常规炮击为主，
   不主动释放全部花式技能；**人方**可完整测试自己所有舰船技能。
4. **扫码解码**：CameraX 取 Y 平面 + ZXing `MultiFormatReader`，按
   `imageInfo.rotationDegrees` 旋转后解码；极端机型/角度识别失败时，
   请用「搜索附近房间」或「手动输入 IP:端口:密钥」兜底。
5. **mDNS 服务类型**用 `_archipelago._tcp`（部分 ROM 对 NSD 有限制），
   因此二维码与手动直连是并列的一等公民通道，不依赖 NSD 成败。
6. 三套主题（坐标纸 / 情报室 / 声呐雷达）的扫描线、折痕、定位十字、同心环、
   命中叉与水花圈都是原创 Canvas 矢量绘制，不依赖任何图片、字体或第三方素材。

## 九、v5 联机可靠性修复（客机进房后无法操作）

### 根因
房主把战况推给客机的 `publish()` 运行在主线程，而 `LanEndpoint.send()` 直接在该线程
写 `Socket`。Android StrictMode 会在主线程网络 IO 上抛 `NetworkOnMainThreadException`，
异常被 `send()` 捕获后误报「连接已断开」，于是：客机收到了 `Assign`（显示"已加入房间"），
却永远收不到第一份 `GameView` → 大厅只剩「正在同步房间…」，没有任何可点的按钮。
另外还有三处隐患会放大这个问题：NSD 服务名带系统后缀导致密钥校验失败后静默无响应、
跨线程各自 `_ui.value = _ui.value.copy(...)` 造成状态丢失、首帧丢失后没有任何补发机制。

### 修改内容
1. **单写线程**：`LanEndpoint` 内部用专用 `newSingleThreadExecutor` 串行投递所有帧，
   任意线程都能安全 `send()`；顺带保证 `Assign` 一定先于补发的 `State`。监听端支持客机断线重连，
   旧读线程用 generation 标记，不会误报"对端已断开"。
2. **握手即带状态**：`Packet.Assign` 新增 `view` 字段，房主在握手应答里直接下发第一份完整
   `GameView`；新增 `Packet.Sync`，客机可主动索要多轮全量状态（首帧丢失后最多自动重试 6 次），
   大厅也加了「重新向房主同步战况」按钮。
3. **身份与状态原子化**：`role / mySide / roomKey / joinKey / guestConnected` 改为 ViewModel
   成员变量，不再依赖易被覆盖的 UiState；所有 UI 写入走 `updateUi` 原子读-改-写，
   网络回调统一切主线程。房主收到任意客机 `Action` 都必回一份 `State`
   （哪怕动作被规则拒绝，客机也能看到提示日志）。
4. **失败可见**：`Wire.decodeDetailed` 把解析/序列化异常原因报出来，显示在首页/大厅的
   「联机诊断：…」和 Toast 中，不再静默丢帧；密钥不匹配、房主拒绝加入都回明确原因；
   NSD 解析出的房间密钥用 6 位数字正则提取，避开系统加的 " (2)" 后缀。
5. **体验兜底**：客机连接期间首页显示进度与「取消连接」；无战况时大厅显示身份/席位、
   重新同步按钮与排障清单；房主离开房间会尝试发 `Bye` 并断连（客机至少会收到断连提示）；
   180 秒超时托管改为按当前行动方执行，
   客机回合挂机也不会卡死房主。

### 双机验证步骤（两台手机务必装**同一版本** APK）
1. 两机连到同一 Wi-Fi，或 A 开热点给 B（热点场景优先用二维码，IP 以房主界面显示为准）。
2. A：创建房间（房主）→ 显示二维码与「房间 IP:端口 · 密钥」。
3. B：扫码加入 / 搜索附近房间 / 手动输入 `IP:端口:密钥`。
4. **预期**：B 立刻进入「战前准备大厅 · ROOM_LOBBY」，能看到地图信息、双方准备状态、
   舰队编成、「选船 / 布阵」「准备完毕」按钮与聊天框；A 端连接文字变成「客机已加入 · 初始战况已下发」。
5. B 点「选船 / 布阵」→「准备完毕」，A 端应实时看到「客机 ✔已准备」；A 也准备后点
   「开始战斗」，两端同时切到棋盘；B 开火后 A 端立刻看到战报。
6. 若 B 停在「正在同步房间战况…」：先看连接文字里的「联机诊断：…」，点「重新向房主同步战况」；
   仍未恢复则让 A 退出重开房间、重新扫码，并确认两机 APK 版本一致、没有隔离子网 / 访客网络隔离。

## 九、v9：侦察 / 拦截 / 鱼雷判定复核 + 水听改造 + 新增雷达哨舰

### 1. 四个实测问题的定位与修正

| 现象 | v8 真实原因 | v9 行为 |
| --- | --- | --- |
| J9 放侦察机直接被击落 | `RECON` 把 `intercepted(board, cells)` 传了**整个十字 5 格**，任一格擦到防空区就判战机被击落（J9 本身在圈外、J10 在圈内） | 只判 `listOf(center)` 部署点；扫描范围和击落范围彻底解耦。被击落时只回一条私有提示，不写任何棋盘标记、不泄露给对手 |
| M14 报「无舰艇」，实际是水下潜艇 | 侦察计数写死 `s.type != SUBMARINE`，把潜艇整体排除 | 水面舰按任意船体格计；水下潜艇按**潜望镜中心格**计（`cells[1]`），不管有没有上浮；上浮后按任意格计 |
| M14 起投、J14 最长射程却够不到 | `torpedoBomberLine()` 写 `for (i in 0..2)`，航线只有「起点 + 2 步」= 3 格，最远 K14 | `TORPEDO_BOMBER_STEPS = 3`，航线 = 起点 + 3 步 = 4 格，M14 → L14/K14/**J14**；航向候选点同步扩到 1..3 格 |
| 被拦截后该格再也不能开炮 | `applyShot()` 对 `INTERCEPTED / IMMUNE / BLOCKED` 也用 `mark=true` 写进了 `attackedPoints`，坐标被永久锁死 | `Board.record()` 只有 MISS/HIT/SUNK 三种真判定才写 `attackedPoints`；拦截/免疫/阻挡只留紫色盾显示标记，坐标完全不封锁，可由其他舰船继续打 |

另外补了两处：
- **AA 圈外视距打击**保持「只看投雷起点」不变，并把这条写进 `aaZone()` / `intercepted()` 注释，
  明确「航线穿过防空区不算被击落」；`applyCross()` 也改为只判中心点。
- 燃烧弹的「AA 瘫痪 1 个敌方回合」原来写 `aaDisabledUntil = round + 1`，
  对先手的 A 来说会延后一整轮才生效；现在按行动方计算：A 命中 → 本 round（B 的下个回合）生效，
  B 命中 → round+1（A 的下个回合）生效。

### 2. 鱼雷遇山 / 无效发射

两种鱼雷（潜航鱼雷 4 格、鱼雷机 3 步）统一「单点爆炸」优先级：
① 航线上第一艘未沉敌舰 → 该格；② 前方是山 → **撞山前一格**；③ 都没有 → 射程尽头一格。
`fireTorpedo()` 现在显式记录 `blockedByMountain`，并回一条私有提示说明炸点；
如果前方第一格就是山 / 边界，`line` 为空时**不消耗该舰行动、不触发强制上浮**（v8 会白白烧掉一回合）。

### 3. 反潜舰 · 主动水听声呐（改造）

- **只探测潜艇**，无视水下隐蔽（首尾格也算），水面舰一律不计入 —— v8 本来就只数潜艇，v9 保持并写进说明。

## 十二、v10：防空复核 / 真随机布阵 / 鱼雷射程台账 / 交互降噪

### 1. 舰载机投弹的 AA 拦截（逐行复核结果）

v9 把「侦察范围 ≠ 击落范围」修好了，但 `applyShot()` 里还留着一条按**炸点**判区域防空的支路：
航母战术轰炸机只要炸到防空巡洋舰周围 15 格里的任意一格（哪怕是空海），都会被判击落。
这既和「飞机只是飞过该区去炸别处不算被击落」冲突，也和鱼雷机「起点在圈外就能打进圈内」自相矛盾。

现在拆成两条互不混用的规则，统一走 `aaShipAt(board, cells, area)`：

| 判定 | 用哪个范围 | 判哪个点 | 影响谁 |
| --- | --- | --- | --- |
| 区域防空网 `area = true` | 航母 5 格 / 防空巡洋舰 15 格 | **部署点**：侦察机中心、鱼雷机投雷起点、范围攻击中心 | 侦察机 / 鱼雷机被击落 |
| 本体点防空 `area = false` | 防空舰自己的船体格（5 / 3 格） | **炸点**：炸弹落点 | 来犯敌机被近防火力击落 |
| `ignoresAA = true` | 不判 | — | 陆航空袭「无视一切 AA」、绝境副炮物理炮击 |

- 航母战术轰炸机从己方航母起飞，部署点天然在敌方防空圈外，**飞过防空区投弹不再被击落**；
  只有炸弹直接落在防空舰本体格时才拦截。区域防空网仍然克制侦察机与鱼雷机。
- 扫描范围、鱼雷航线、爆炸点一律不参与区域防空判定。
- 炮艇「灵活规避」提到防空判定之前，避免它停在防空舰本体格时被误报成「拦截」而不是「免疫」。
- 顺带查出的真 bug：燃烧弹命中后 `aaDisabledUntil` 对房主写 `round`、对客机写 `round+1`，
  导致客机刚打中防空舰、自己本回合剩余空中行动却仍被拦截。现在双方统一写当前 `round`，
  判定改成 `state.round <= aaDisabledUntil`，压制当回合立即生效、下一回合恢复。
- 拦截 / 免疫 / 阻挡依旧不写 `attackedPoints`，换艘舰还能打同一格。

### 2. 一键随机布阵：真的能排出多种阵型

v9 的按钮固定传 `cfg.seed + 31`，而 `cfg.seed` 只在房主改地图时才变 ——
**每次点都是同一套阵型**，属于伪随机。现在：

- 每次点「一键随机布阵」都用 `Random.nextLong()` 新种子；
- `Rules.defaultPlacements(config, fleet, seed, style)` 先生成一批合法候选，再按风格打分挑选：
  **均衡散布**（随机取合法候选）/ **边角分散**（贴边 + 尽量互相远离）/
  **中央集结**（靠中心 + 互相靠拢）/ **同向编队**（5 艘统一横或纵）；
- 候选池为空时退回全盘穷举，保证 5 艘一定放完；UI 提供 4 个风格切换按钮与「已生成 N 套方案」反馈；
- **放置成功后停留在当前槽位**，可以反复点不同格子微调同一艘；另给「下一未布置槽」按钮显式换槽，
  解决「想调整某一舰种、一放上去就自动切到下一条船」的问题。

### 3. 潜艇受击复核 + 同向鱼雷递减射程

- `canBeHit()` 原来把 `AIR_CROSS / LAND_AIR` 一律判 false，导致「无视一切 AA 的饱和轰炸」
  连露出水面的潜望镜中心格都打不到；现在与非航空攻击一致，只能打中心格（深弹 / 鱼雷仍打整艇）。
- 上浮暴露复核先排除「已被深弹 / 鱼雷打穿」的格子，避免同一格重复计一次伤害。
- 新增 `Ship.torpedoLanes: Map<String, Int>`：四个方向各自记剩余推进格数，
  默认 4，每成功发射一次该方向变成 `本次最远推进距离 - 1`，于是同向连射依次落在 **4 / 3 / 2 / 1** 格，
  归零后该方向拒绝发射且不消耗行动；换方向不受影响。
- **炸点写进 `attackedPoints`（mark = true）**：既防止同格被多枚鱼雷重复结算，
  也让后续同向鱼雷遇到「已炮击 / 已炸过」的格子自动截断、在其前一格引爆；
  前方第一格就被封死时整次发射无效、不触发强制上浮。中间格依旧不锁、仍可用火炮打击。
- 棋盘候选格随各方向剩余射程收缩，提示行直接显示「北 N 格 · 南 N 格 · 西 N 格 · 东 N 格」。

### 4. 交互与视觉

- **情报视图（默认开）**：不显示任何可打击方格，画面只留地形 / 战果 / 四种情报层；
  点任意格子弹出该格检查卡（地形、最近判定、是否已封锁、侦察 / 水听 / 雷达 / 空袭预告覆盖）。
  选船 → 点格 → 确认开火照常可用，不需要来回切模式；对方回合也能点开看信息。
- **完整战报**：顶部固定最近 3 条，点按钮打开整屏面板一次看完，去掉页面内 150dp 嵌套滚动列表。
- **降噪**：`BoardCanvas(calm)` 压掉交错格明暗跳变、手绘细网格、声呐同心圆与扫描扇形；
  可打击标记从每格 8 条四角括号 + 中心点，改成 1 个内缩描边框 + 1 个角点（14×14 少画近 2000 条线段）；
  三套主题同步调低 `waterAlt` 对比、抬高 `legalInk` 与水面反差、加深「已打过」斜纹。
